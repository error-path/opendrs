A 0–1 risk score for every pull request

AI writes code and AI reviews it, so the final human review is now the bottleneck. opendrs scores each PR's risk from its blast radius and history, tells your AI reviewer where to look, and tells the last human reviewer how much attention the PR needs and what the editor and the AI rounds didn't show. Low-risk PRs can be approved and merged on their own.

What the score measures

Every signal comes from your own git history and code, and every one is reported with its evidence, so you can see why a PR scored what it did.

Blast radius
How many files transitively import the changed code, and whether exported or public declarations changed.
File history
Past fixes, reverts and recorded incidents in the touched files and folders.
Author experience
How much the author has changed these files before, and whether they wrote them.
Size and spread
Changed lines relative to file size, and how many files, folders and past authors are involved.
Tests
Source changed without test changes, or tests deleted.
Critical paths
Files you mark as critical, such as payments or auth, raise the score.

How a pull request gets approved

The Action checks these in order. A PR is approved only if it gets through all of them.

  1. No changed file is on a blocked path: workflows, build and install scripts, migrations, infrastructure, CODEOWNERS and the opendrs config itself.
  2. No safety rule fires: ignored files such as lockfiles, binary files, submodule changes, deleted tests, blocklisted code phrases, or a change larger than your size cap.
  3. The score is in the green tier, no freeze window holds it back, and no unknown signal could have changed the tier.
  4. The PR is not a draft, and no reviewer has requested changes.
  5. Your required AI-review check has passed on the latest commit.
  6. A random sample of eligible PRs (10% by default) still goes to a human, so you keep measuring what the gate lets through.
  7. The PR is approved and auto-merge is enabled, or it joins the merge queue. A later, riskier push withdraws the approval.

Why you can trust the number

It is measured on your historyopendrs backtest replays past commits and reports how many bug-introducing changes the score would have caught. opendrs calibrate fits the model to your repository. On nine open-source repositories, calibration improved accuracy on held-out commits in every one.

A PR cannot turn it offThe config and model are read from the base branch. The Action never approves changes to its own config or to CI, and never approves PRs from forks.

Unknown is never safeA signal that cannot be computed blocks approval whenever it could have changed the tier. A failed LLM answer counts the same way.
